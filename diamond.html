Diamond

“By the end of this tranche, CHIRP must be able to access well-structured data from the 2 existing and up to 6 additional jurisdictions’ reports via an LLM (our own or a 3rd party) to compare incidents, identify recurring patterns and synthesise lessons with conclusions traceable to the underlying source reports.”

CHIRP’s requirements

  • Reports from the UK, the US and up to 6 more countries
  • CHIRP’s own reports
  • Asked through an AI, CHIRP’s own or a third party’s
  • Compare incidents, find recurring patterns and draw lessons
  • Every conclusion traceable to its source report
  • SHIELD matching
  • Kept up to date automatically
  • A validated test set
  • Logging
  • Stretch: open to people CHIRP shares the link with

Glossary

  • Connector. A small new service that users add to the Claude harness. It holds no data: it turns the AI’s requests into calls to CHIRPdb, which does the searching and counting. Users sign in with a CHIRPdb account before it works.
  • Shared vocabulary. Each country describes the same thing in its own words: one says “fishing vessel”, another “fishing”, another “trawler”; severity and accident type vary in the same way. We map every country’s terms onto one list for each field, building on the IMO classifications we already use for accident type and severity. We also capture more fields from every report, so a report from any country carries close to the detail the MAIB spreadsheets give. The result: ask about fishing vessel groundings and the answer draws on the matching reports from every country, with counts that compare like with like.
  • Review tool. The part of the CHIRPdb frontend that CHIRP staff use to check reports.
  • Fast ingestion. 2.5 days per country instead of 5. Only some of each country’s reporting rules are built in, so the data is less reliable.
  • Validated test set. A fixed list of questions with known right answers, re-run after every change to catch answers getting worse.
  • Pattern finding and learning from user questions. Asking what keeps recurring across all reports, for example what keeps causing enclosed-space deaths, and seeing the supporting cases. Every report has two parts. The metadata is a set of labelled details held for every report: country, date, vessel type, accident type, outcome and SHIELD codes. The plain text is the report itself, the investigators’ written account of what happened. Included in Diamond Finding what recurs across every report. Claude uses a CHIRPdb tool that searches every report in the database, both its metadata and its plain text, not just a handful of top matches. Claude decides what to look for, for example enclosed-space deaths by SHIELD code, vessel type and country, or a phrase such as “double shift” in the text, then compares the results and writes up the lessons. Counts from the metadata are exact, so every number traces back to its reports. Not included in Diamond Patterns in the plain text, and learning. Patterns that appear only in the text are harder: the system has to read the reports to spot them. For example, many reports may mention that the crew had just finished a double shift, but no field records it, so Diamond cannot count it. With learning, the system would spot it in the text and save “crew had just worked a double shift” against each report it applies to, in effect a new piece of metadata. The next time anyone asks something similar, the system checks the metadata first, then the saved findings, and only then goes back to the plain text, so answers get faster and more consistent with every question. Diamond logs every question, which is the starting point for this.
  • Causal AI. Working out which factors actually cause accidents, not just which ones appear together. CHIRP’s experts propose a cause, for example that fatigue leads to groundings, and the system tests it against the reports, showing how strong the effect is; nothing is cited until CHIRP signs it off. It also tests whether a regulation or recommendation worked. Diamond shows what recurs, not what causes what.
  • Log. A record of each question asked and which reports the AI used to answer it.
