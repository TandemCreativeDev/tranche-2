Diamond

By the end of this tranche, CHIRP can ask an AI about reports from 8 countries to compare incidents, find recurring patterns and draw lessons, with every conclusion traced back to its source report.

CHIRP’s requirements

  • Reports from the UK, the US and up to 6 more countries
  • CHIRP’s own reports
  • Asked through an AI, CHIRP’s own or a third party’s
  • Compare incidents, find recurring patterns and draw lessons
  • Every conclusion traceable to its source report
  • SHIELD matching
  • Kept up to date automatically
  • A validated test set
  • Logging
  • Stretch: open to people CHIRP shares the link with

Glossary

  • Connector. A plug-in users add to their own AI, such as Claude, so it can search CHIRPdb. Users sign in with a CHIRPdb account before it works.
  • Shared vocabulary. Each country describes the same thing in its own words: one says “fishing vessel”, another “fishing”, another “trawler”; severity and accident type vary in the same way. We map every country’s terms onto one list for each field, building on the IMO classifications we already use for accident type and severity. We also capture more fields from every report, so a report from any country carries close to the detail the MAIB spreadsheets give. The result: ask about fishing vessel groundings and the answer draws on the matching reports from every country, with counts that compare like with like.
  • Review tool. CHIRP’s existing staff screen for checking reports.
  • Fast ingestion. 2.5 days per country instead of 5. Only some of each country’s reporting rules are built in, so the data is less reliable.
  • Validated test set. A fixed list of questions with known right answers, re-run after every change to catch answers getting worse.
  • Pattern finding and learning. Asking what keeps recurring across all reports, for example what keeps causing enclosed-space deaths, and seeing the supporting cases. Every report has two parts. The metadata is a set of labelled details held for every report: country, date, vessel type, accident type, outcome and SHIELD codes. The plain text is the report itself, the investigators’ written account of what happened. Included Patterns in the metadata. These are quick and reliable to find, because the system simply counts across every report. Not included Patterns in the plain text, and learning. Patterns that appear only in the text, such as something about the crew’s background, are harder: the system has to read the reports to spot them. With learning, whatever it finds is saved against each report it applies to, in effect a new piece of metadata. The next time anyone asks something similar, the system checks the metadata first, then the saved findings, and only then goes back to the plain text, so answers get faster and more consistent with every question. Diamond logs every question, which is the starting point for this.
  • Log. A record of each question asked and which reports the AI used to answer it.
